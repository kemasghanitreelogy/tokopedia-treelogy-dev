## 2. Problem Statement

The seller (Treelogy Moringa) completed authorization, but the resulting `auth_code`
was delivered to an external Vercel redirect URL that does not exchange it. No
`access_token` was ever persisted. Every shop-level endpoint requires
`x-tts-access-token`, so the integration is blocked at step one.

## 3. Constraints

- C1. `redirect_url` is fixed in Partner Center and points outside this repo — a local
      loopback callback is not possible. The auth_code must be transferred manually.
- C2. `auth_code` is short-lived and single-use.
- C3. Secrets must never enter the chat transcript → hidden stdin prompt, no argv.
- C4. `.env` is currently untracked with no `.gitignore` → leak risk on first commit.
- C5. Zero runtime dependencies (Node 25 has fetch/crypto/readline built in).

## 4. Phases

### Phase 1 — Repository safety (blocking)
1.1 Create `.gitignore` covering `.env`, `.env.*`, `node_modules`, tokens
1.2 Create `.env.example` documenting every key
1.3 Verify `.env` is not staged in git

### Phase 2 — Core primitives
2.1 `src/env-file.js` — order/comment-preserving `.env` reader + atomic writer (mode 0600)
2.2 `src/config.js` — load, merge process.env, validate required keys
2.3 `src/sign.js` — verified HMAC-SHA256 signer + `signedUrl()` helper

### Phase 3 — OAuth lifecycle
3.1 `src/auth.js` `buildAuthorizeUrl()` — authorize URL with CSRF `state`
3.2 `src/auth.js` `exchangeAuthCode()` — `/api/v2/token/get`
3.3 `src/auth.js` `refreshAccessToken()` — `/api/v2/token/refresh`
3.4 Persist `ACCESS_TOKEN`, `REFRESH_TOKEN`, expiries, `OPEN_ID` into `.env`

### Phase 4 — Signed API client
4.1 `src/client.js` — inject `app_key`/`timestamp`/`shop_cipher`, sign, send
4.2 Auto-refresh once on `36009005` / local expiry, then retry
4.3 Normalize `{code, message, data, request_id}`; treat `code != 0` as failure

### Phase 5 — Shop discovery
5.1 `GET /authorization/202309/shops` → shop list
5.2 Persist `SHOP_ID`, `SHOP_CIPHER`, `SHOP_NAME`
5.3 Resolve open question: does the ID/Tokopedia shop resolve on the global host

### Phase 6 — CLI + doctor
6.1 `bin/tts.mjs` dispatch: `url | exchange | refresh | shops | doctor | api`
6.2 `doctor` — 7 sequential checks, actionable remediation per failure
6.3 `api` — generic signed caller for any endpoint

### Phase 7 — Validation
7.1 Offline: signature vector, `.env` round-trip, expiry math
7.2 Live: unsigned probe, signed probe, `doctor`
7.3 `README.md` runbook
